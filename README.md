# أسطول (Astol) - نظام إدارة الأساطيل وصيانة المركبات

نظام سحابي مؤسسي متكامل لإدارة أساطيل المركبات وجداول الصيانة الدورية وقطع الغيار وأذونات التشغيل والرحلات وسجلات الوقود والتقارير الرقابية، مبني وفق أحدث المعايير البرمجية.

---

## 1. نبذة عن النظام (Project Overview)

تم تصميم وتطوير نظام **أسطول** لتمكين الشركات التي تمتلك وتدير أساطيل مركبات من تتبع دورة الحياة التشغيلية الكاملة لكل مركبة:
- إصدار أذونات التشغيل ورحلات العمل وتتبع وقت الانطلاق ووقت العودة وعدادات البداية والنهاية واحتساب المسافات تلقائياً.
- ضبط وإلزام قواعد حركة العدادات (Odometer History) ومنع تناقص قراءة العداد قطعياً.
- محرك ذكي لقواعد الصيانة الدورية الوقائية (Maintenance Rule Engine) مبني على المسافة والأيام المنقضية وتوليد التنبيهات الذكية (حرجة، تحذيرية، عادية).
- كتالوج شامل لقطع الغيار وجدولة صلاحية واستبدال القطع لكل مركبة على حدة.
- رقابة وسجلات التزود بالوقود وتحليل تكلفة الكيلومتر ومتوسط الاستهلاك.
- إدارة السائقين وسجلات إسناد المركبات التاريخية.
- مركز تقارير متقدم يحتوي على 14 تقريراً تخصصياً مع دعم الفلترة والبحث والطباعة المباشرة بتنسيق RTL احترافي والتصدير إلى Excel.
- سجل تدقيق أمني وإداري كامل (Audit Log) لتتبع كافة التغييرات والعمليات الحساسة.
- واجهة مستخدم عربية بالكامل 100% بتصميم حديث يدعم اتجاه اليمين لليسار (RTL) متوافق مع كافة الشاشات (كمبيوتر، أجهزة لوحية، هواتف).

## 2. الهيكلية التقنية (Tech Stack & Architecture)

- **الواجهة الأمامية (Frontend)**:
  - إطار العمل: Angular 22 (Standalone Components, TypeScript 5, RxJS).
  - التصميم والسمة: RTL بالكامل، خط Cairo، تصميم مؤسسي عالي التباين والأناقة.
  - الحماية: Route Guards (`authGuard`, `adminGuard`), Functional JWT Interceptor.
- **الواجهة الخلفية (Backend)**:
  - إطار العمل: Python 3.14 + Django 6.1 + Django REST Framework 3.18.
  - التوثيق: JWT (JSON Web Tokens) عبر `djangorestframework-simplejwt`.
  - الصلاحيات: Role-Based Access Control (RBAC) مطبقة برمجياً على كافة مسارات الـ API.
  - معالجة البيانات والتصدير: `openpyxl` لتوليد ملفات Excel المنسقة بـ RTL.
- **قاعدة البيانات (Database)**:
  - MySQL / MariaDB (مع دعم التشغيل المحلي التلقائي المتوافق).

## 3. أدوار المستخدمين وصلاحياتهم (User Roles & Permissions)

| الدور | الاسم في النظام | الصلاحيات والمسؤوليات |
|---|---|---|
| **مدير النظام (Admin)** | `ADMIN` | أعلى صلاحية في النظام: إدارة المستخدمين، تعديل إعدادات عتبات الصيانة، الاطلاع على سجل التدقيق الأمني، وكافة عمليات الإضافة والتعديل والحذف لكافة الوحدات. |
| **مسؤول التشغيل (Operator)** | `OPERATOR` | إدارة العمليات التشغيلية اليومية: إضافة وتعديل المركبات، تسجيل قراءات العدادات، إصدار واعتماد وبدء وإنهاء أذونات التشغيل، تسجيل عمليات الصيانة واستبدال القطع، تسجيل وقود، ولا يملك حق إدارة المستخدمين أو الإعدادات العامة. |
| **مراقب التقارير (Reporter)** | `REPORTER` | قراءة فقط (Read-Only): الاطلاع على لوحة التحكم، استعراض بيانات المركبات والرحلات والصيانة والوقود، توليد وطباعة وتصدير كافة التقارير الـ 14، وممنوع برمجياً في الـ Backend من إجراء أي تعديل أو حذف أو إضافة. |

## 5. قواعد العمل الصارمة (Strict Business Rules)

1. **قاعدة العدادات (Odometer Integrity)**:
   - لا يمكن للعداد أن يتناقص أبداً.
   - أي قراءة جديدة يتم إدخالها يجب أن تكون $\ge$ القراءة الحالية المسجلة للمركبة.
   - لا يتم استبدال القراءة القديمة دون الاحتفاظ بها، بل تُحفظ كل قراءة في جدول `OdometerReading` التاريخي مع توثيق المصدر والمستخدم ووقت الإدخال.
2. **دورة حياة أذونات التشغيل والرحلات (Work Permit Workflow)**:
   - المسار: `مسودة (DRAFT) -> معتمد (APPROVED) -> قيد التنفيذ (IN_PROGRESS) -> مكتمل (COMPLETED)`.
   - لا يمكن بدء رحلة لمركبة بحالة "خارج الخدمة (OUT_OF_SERVICE)" أو "في الصيانة (IN_MAINTENANCE)".
   - منع تداخل رحلتين نشطتين لنفس المركبة في نفس الوقت.
   - عند بدء الرحلة: يتم تسجيل وقت الانطلاق الفعلي وعداد البداية ($\ge$ عداد المركبة).
   - عند إتمام الرحلة: يتم تسجيل وقت العودة الفعلي وعداد العودة، والتحقق الصارم من أن `عداد العودة >= عداد البداية`.
   - احتساب المسافة المقطوعة تلقائياً: `المسافة = عداد العودة - عداد البداية`.
   - تحديث عداد المركبة الحالي تلقائياً إلى عداد العودة، وتشغيل محرك قواعد الصيانة لفحص كافة قطع المركبة وتحديث التنبيهات.
3. **محرك الصيانة الوقائية والتنبيهات (Maintenance Rule Engine)**:
   - حساب حالة كل قطعة مركبة بناءً على:
     - الكيلومترات المتبقية: `العداد القادم - العداد الحالي للمركبة`.
     - الأيام المتبقية: `تاريخ الاستبدال القادم - اليوم`.
   - تحديد الحالة آلياً:
     - `متأخر (OVERDUE)`: إذا كانت الكيلومترات المتبقية $\le 0$ أو الأيام $\le 0$ (تنبيه حرج CRITICAL).
     - `مستحق قريباً (DUE_SOON)`: إذا كانت الكيلومترات المتبقية $\le$ الحد المخصص (افتراضياً 1,000 كم) أو الأيام $\le$ 14 يوماً (تنبيه تحذيري WARNING).
     - `قادم (UPCOMING)`: إذا كانت الكيلومترات المتبقية $\le$ 2,500 كم أو الأيام $\le$ 30 يوماً.
     - `سليم (OK)`: تعمل القطعة بكفاءة.
   - فحص تواريخ انتهاء الوثائق والتراخيص (استمارة، تأمين، فحص دوري، رخص السائقين) وتوليد تنبيهات فورية عند قرب أو حلول موعد انتهائها.
4. **سجلات الوقود (Fuel Records)**:
   - احتساب التكلفة الإجمالية تلقائياً: `الكمية * سعر اللتر`.
   - تحديث عداد المركبة تلقائياً إذا كانت قراءة عداد الوقود أعلى من القراءة المسجلة.
5. **سجل التدقيق الأمني (Audit Trail)**:
   - تسجيل كافة الأحداث الحساسة (تسجيل الدخول، انطلاق الرحلات، إتمام الرحلات، إلغاء الأذونات، تحديث العدادات، تسجيل الصيانة، استبدال القطع، تعديل المركبات والمستخدمين) متضمناً معرّف المستخدم، عنوان IP، والتفاصيل.

## 6. خطوات التثبيت والتشغيل (Setup & Execution Guide)

### أولاً: متطلبات البيئة
- Python 3.11+ (أو 3.14)
- Node.js v20+ و npm
- خادم MySQL / MariaDB (أو استخدام البيئة المحلية المدمجة)

### ثانياً: إعداد وتشغيل الواجهة الخلفية (Backend)

1. الانتقال إلى مجلد الواجهة الخلفية وتفعيل البيئة الافتراضية:
```bash
cd backend
.\venv\Scripts\activate
```

2. تثبيت الحزم (إن لم تكن مثبتة):
```bash
pip install -r requirements.txt
```

3. ضبط متغيرات البيئة (اختياري لقاعدة بيانات MySQL):
قم بإنشاء ملف `.env` داخل مجلد `backend`:
```ini
SECRET_KEY=your-production-secret-key
DEBUG=True
USE_MYSQL=True
DB_NAME=astol_fleet_db
DB_USER=root
DB_PASSWORD=your_password
DB_HOST=127.0.0.1
DB_PORT=3306
```
*(ملاحظة: في حال ضبط `USE_MYSQL=False`، سيعمل النظام تلقائياً على قاعدة بيانات SQLite المحلية لسهولة التطوير والاختبار).*

4. تطبيق ترحيل الجداول (Migrations):
```bash
python manage.py migrate
```

5. بذر البيانات التأسيسية والواقعية (Seed Data):
```bash
python manage.py seed_data
```

6. تشغيل الاختبارات المؤتمتة الشاملة (19 اختبار):
```bash
python manage.py test core
```

7. تشغيل خادم التطوير للواجهة الخلفية:
```bash
python manage.py runserver 127.0.0.1:8000
```

---

### ثالثاً: إعداد وتشغيل الواجهة الأمامية (Angular Frontend)

1. الانتقال إلى مجلد الواجهة الأمامية:
```bash
cd ../frontend
```

2. تثبيت حزم npm (إن لم تكن مثبتة):
```bash
npm install
```

3. فحص البناء والتحقق من سلامة الأكواد:
```bash
npm run build
```

4. تشغيل خادم التطوير للواجهة الأمامية:
```bash
npm start
```
سيكون التطبيق متاحاً على الرابط: `http://localhost:4200`

## 7. نظرة على التقارير المتوفرة في النظام (14 تقريراً)

1. **تقرير أسطول المركبات الشامل (Vehicle Report)**: جرد تفصيلي لكافة مركبات الأسطول وحالاتها وأقسامها وسائقيها.
2. **تقرير تشغيل واستخدام المركبات (Vehicle Usage Report)**: إحصاءات الرحلات والمسافات المقطوعة واستهلاك الوقود لكل مركبة.
3. **تقرير أذونات التشغيل (Work Permit Report)**: سجل تفصيلي لكافة أذونات التشغيل الصادرة ومساراتها وغاياتها.
4. **تقرير الرحلات المكتملة (Trip Report)**: رحلات العمل الميدانية المنجزة وعدادات البداية والعودة والمسافات.
5. **تقرير عمليات الصيانة والإصلاح (Maintenance Report)**: كافة العمليات الدورية والطارئة مع تكاليفها ومزودي الخدمة.
6. **تقرير تحليل تكاليف الصيانة (Maintenance Cost Report)**: تحليل مالي لمصروفات الصيانة لكل مركبة ومتوسط تكلفة العمليات.
7. **تقرير أداء واستبدال قطع الغيار (Parts Replacement Report)**: تتبع صلاحية كل قطعة غيار والكيلومترات والأيام المتبقية.
8. **تقرير سجلات تعبئة الوقود (Fuel Report)**: حركات التزود بالوقود والكميات والمحطات والتكاليف.
9. **تقرير تحليل تكاليف الوقود (Fuel Cost Report)**: إجمالي مصروفات ولترات الوقود لكل مركبة.
10. **تقرير سجل وحركات العدادات (Odometer Report)**: التدقيق الزمني لحركة قراءات العدادات ومصادرها.
11. **تقرير نشاط وأداء السائقين (Driver Activity Report)**: المسافات المقطوعة وعدد الرحلات المنجزة لكل سائق.
12. **تقرير الوثائق والتراخيص المنتهية (Expiring Documents Report)**: استمارات وتأمينات وفحوصات دورية ورخص قاربت أو تجاوزت موعد التجديد.
13. **تقرير الصيانات المتأخرة الحرجة (Overdue Maintenance Report)**: القطع والخدمات التي تجاوزت المسافة المسموحة وتتطلب فحصاً فورياً.
14. **تقرير الصيانات القادمة والمستحقة قريباً (Upcoming Maintenance Report)**: جدول الصيانة الاستباقي للأيام والكيلومترات القادمة.

## 8. دليل النشر للإنتاج (Production Deployment)

1. **الواجهة الخلفية (Django + Gunicorn + Nginx)**:
   - تفعيل `DEBUG = False`.
   - توليد مفتاح سري عشوائي مشفر `SECRET_KEY`.
   - ضبط `ALLOWED_HOSTS = ['yourdomain.com']`.
   - جمع الملفات الثابتة: `python manage.py collectstatic --noinput`.
   - تشغيل الخادم عبر خادم WSGI مثل `gunicorn astol_project.wsgi:application --bind 127.0.0.1:8000 --workers 4`.
2. **الواجهة الأمامية (Angular Build)**:
   - بناء النسخة الإنتاجية: `npm run build`.
   - يتم تصدير الملفات المحسنة والمضغوطة إلى مجلد `frontend/dist/astol-frontend/browser`.
   - ضبط Nginx لتخديم الملفات كـ Static Files مع توجيه المسارات إلى `index.html` لدعم الـ SPA Routing.
3. **تكوين Nginx**:
```nginx
server {
    listen 80;
    server_name fleet.yourcompany.com;

    # Frontend
    location / {
        root /var/www/astol/frontend/dist/astol-frontend/browser;
        try_files $uri $uri/ /index.html;
    }

    # Backend API
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # Static & Media
    location /static/ {
        alias /var/www/astol/backend/staticfiles/;
    }
    location /media/ {
        alias /var/www/astol/backend/media/;
    }
}
```
