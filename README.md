# أسطول (Astol) - نظام إدارة الأساطيل وصيانة المركبات

نظام سحابي مؤسسي متكامل لإدارة أساطيل المركبات وجداول الصيانة الدورية وقطع الغيار وأذونات التشغيل والرحلات وسجلات الوقود والتقارير الرقابية، مبني وفق أحدث المعايير البرمجية على بيئة **PostgreSQL + Django REST Framework + Angular 22**.

---

## 1. نبذة عن النظام (Project Overview)

تم تصميم وتطوير نظام **أسطول** لتمكين المنشآت والشركات التي تمتلك وتدير أساطيل مركبات من تتبع دورة الحياة التشغيلية الكاملة لكل مركبة:
- **نظام عداد آلي متسلسل** للرقم الداخلي للمركبة (`FL-101`, `FL-102`...).
- **قوائم منسدلة ديناميكية (Dynamic Dropdowns)** لطرازات المركبات، الألوان، أنواع الوقود، والأقسام.
- **صفحة مركزية للأدمن (`/lookups`)** لإدارة كافة القوائم والكتالوجات بـ Full CRUD كامل.
- **إصدار أذونات التشغيل ومودال اكتمال الرحلة** مع تحديد مكان انطلاق الرحلة وتحديث قراءة العداد في النظام بالكامل فور إتمام الرحلة.
- **أتمتة تسعير الوقود** بناءً على السعر والعملة المحددة لكل نوع وقود من قبل الإدارة.
- **ضبط وإلزام قواعد حركة العدادات (Odometer Integrity)** ومنع تناقص قراءة العداد قطعياً.
- **محرك ذكي لقواعد الصيانة الدورية الوقائية (Maintenance Rule Engine)** يربط فواصل الكيلومتر والأيام بكتالوج قطع الغيار وتوليد التنبيهات.
- **إدارة قطع الغيار واختيارها من دروب داون منسدل** مع تحديد مسافة التغيير وعتبة التحذير للسماحية المسبقة.
- **مركز التنبيهات والإشعارات** مع دعم حالة **"تم حل المشكلة"** بالإضافة إلى "تم الاطلاع".
- **تخصيص الصلاحيات الصارم (RBAC)** ومنع مسؤولي التشغيل من إضافة أو تعديل المركبات وحصرها بالمدير.
- **مركز تقارير متقدم (14 تقريراً)** مع دعم الفلترة والطباعة المباشرة والتصدير إلى Excel بتنسيق RTL.
- **سجل تدقيق أمني وإداري كامل (Audit Log)** لتتبع كافة العمليات الحساسة.
- **واجهة مستخدم عربية 100% بتصميم عصري وأنيق (RTL)**.

## 2. الهيكلية التقنية للبروجيكت (Technology Stack)

```
┌─────────────────────────────────────────────────────────────────┐
│                     Astol Fleet Management System               │
├─────────────────┬───────────────────────────────┬───────────────┤
│    Frontend     │            Backend            │   Database    │
├─────────────────┼───────────────────────────────┼───────────────┤
│ Angular 22      │ Python 3.14 + Django 6.1      │ PostgreSQL    │
│ Standalone Comp │ Django REST Framework 3.18    │ (Primary)     │
│ TypeScript 5    │ SimpleJWT (Token Auth)        │ + psycopg2    │
│ RxJS 7.8        │ Audit Logging & Rule Engine   │ + SQLite Dev  │
│ Pure RTL Design │ Excel Export (openpyxl)       │ Fallback      │
└─────────────────┴───────────────────────────────┴───────────────┘
```

- **الواجهة الأمامية (Frontend)**:
  - إطار العمل: **Angular 22** (Standalone Components, TypeScript 5, RxJS).
  - التصميم والسمة: RTL بالكامل، خط Cairo، تصميم مؤسسي عالي التباين والأناقة.
  - الحماية: Route Guards (`authGuard`, `adminGuard`), Functional JWT Interceptors.
- **الواجهة الخلفية (Backend)**:
  - إطار العمل: **Python 3.14 + Django 6.1 + Django REST Framework 3.18**.
  - التوثيق: JWT (JSON Web Tokens) عبر `djangorestframework-simplejwt`.
  - الصلاحيات: Role-Based Access Control (RBAC) مطبقة برمجياً على كافة مسارات الـ API.
  - محرك التقرير: `openpyxl` لتوليد ملفات Excel المنسقة بـ RTL.
- **قاعدة البيانات (Database)**:
  - **PostgreSQL 15+ / 16+**: قاعدة البيانات الرسمية المعتمدة للإنتاج والمشروع عبر محرك `django.db.backends.postgresql` ومكتبة `psycopg2-binary`.
  - **نظام التوافق الذكي (Zero-Friction Fallback)**: في حال عدم تشغيل خادم بوستجريس محلياً أثناء التطوير أو المعاينة السريعة، يقوم النظام بالعمل تلقائياً على قاعدة بيانات SQLite المحلية (`db.sqlite3`) المجهزة بنفس البيانات لمنع توقف السيرفر.

## 3. أدوار المستخدمين وصلاحياتهم (User Roles & Permissions)

| الدور | الاسم في النظام | الصلاحيات والمسؤوليات |
|---|---|---|
| **مدير النظام (Admin)** | `ADMIN` | أعلى صلاحية في النظام: إضافة وتعديل وحذف المركبات (Full CRUD)، إدارة القوائم المنسدلة والكتالوجات وتسعير الوقود (`/lookups`)، إدارة المستخدمين، الاطلاع على سجل التدقيق الأمني، والتحكم الشامل. |
| **مسؤول التشغيل (Operator)** | `OPERATOR` | إدارة العمليات التشغيلية اليومية: إصدار واعتماد وبدء وإنهاء أذونات التشغيل، إدخال عداد العودة، تسجيل عمليات الصيانة، تسجيل تعبئة الوقود. **(محظور برمجياً من إضافة أو تعديل أو حذف المركبات)**. |
| **مراقب التقارير (Reporter)** | `REPORTER` | قراءة فقط (Read-Only): الاطلاع على لوحة التحكم، استعراض بيانات المركبات والرحلات والصيانة والوقود، توليد وطباعة وتصدير كافة التقارير الـ 14، وممنوع برمجياً من إجراء أي تعديل أو حذف. |

## 5. قواعد العمل والخصائص المنفذة (Key Features & Rules)

1. **العداد الآلي للرقم الداخلي للمركبة (Auto Fleet Counter)**:
   - يتم توليد الرقم الداخلي للمركبة آلياً بنظام عداد متسلسل تصاعدي (`FL-101`, `FL-102`...).
   - يظهر في واجهة الإضافة للقراءة فقط مع شارة "عداد تلقائي".
2. **القوائم المنسدلة والصفحة المركزية (`/lookups`)**:
   - صفحة كاملة للأدمن لإدارة القوائم: (طرازات المركبات، الألوان مع باليت الألوان، أنواع وأسعار الوقود، الأقسام، كتالوج قطع الغيار، فئات المركبات، أنواع الصيانة).
   - كتالوج قطع الغيار يتضمن: فاصل الاستبدال بالكيلومتر، وعتبة التحذير للسماحية المسبقة بالكيلومتر.
3. **أذونات التشغيل واكتمال الرحلة (Trip Completion)**:
   - تحديد مكان انطلاق الرحلة (`departure_location`).
   - إمكانية إصدار الإذن مباشرة بحالة معتمد/صادر (`APPROVED`).
   - زر "الرحلة اكتملت" يفتح نافذة منبثقة (Popup Modal) تسأل عن عداد العودة، وتحدث قراءة عداد المركبة في النظام بالكامل فورياً وتتحقق من فواصل الصيانة.
4. **أتمتة تسعير الوقود (Fuel Pricing)**:
   - الأدمن يحدد سعر اللتر والعملة لكل نوع وقود.
   - في تسجيل التفويل، اختيار نوع الوقود يدرج سعر اللتر تلقائياً ويحسب التكلفة الإجمالية مباشرة.
5. **الصيانة وقطع الغيار**:
   - اختيار القطع المستبدلة من دروب داون منسدل وإضافتها كبطاقات مع إمكانية الإزالة وإعادة ضبط الفواصل آلياً.
6. **مركز التنبيهات وحالة "تم حل المشكلة"**:
   - إمكانية تحديد حالة التنبيه "تم حل المشكلة" وتوثيق تاريخ الحل، مع فلترة التنبيهات النشطة والمحلولة.

## 6. خطوات التثبيت والتشغيل مع PostgreSQL (Setup & Execution Guide)

### أولاً: المتطلبات
- **Python 3.11+** إلى 3.14
- **Node.js v20+** أو v22
- **خادم PostgreSQL 15+ / 16+** (أو تشغيل خادم محلي / Docker / سحابة)

---

### ثانياً: إعداد وتشغيل خادم PostgreSQL ونقل البيانات

1. تأكد من تشغيل خادم PostgreSQL على جهازك.
2. عدّل ملف `backend/.env` للتأكد من إعدادات الاتصال:
```ini
USE_POSTGRESQL=True
DB_NAME=astol_fleet_db
DB_USER=postgres
DB_PASSWORD=postgres
DB_HOST=127.0.0.1
DB_PORT=5432
```

3. **تشغيل أداة التهيئة ونقل البيانات إلى PostgreSQL تلقائياً:**
قُمنا بإنشاء سكربت ذكي `init_postgres.py` يقوم بإنشاء قاعدة البيانات `astol_fleet_db` على خادم PostgreSQL، وتطبيق الـ Migrations، ونقل واستيراد كافة بيانات الأسطول المنقولة من `datadump.json`:
```powershell
cd backend
.\venv\Scripts\activate
python init_postgres.py
```

*(أو يدوياً عبر أوامر دجانغو القياسية):*
```powershell
python manage.py migrate
python manage.py loaddata datadump.json
```
